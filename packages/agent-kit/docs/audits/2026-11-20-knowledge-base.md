# CyberMP Agent Kit knowledge base audit

State of the kit at commit `14865c9`. Cross-checked against `@cybermp/server-types@3.2.8`, `@cybermp/client-types@2.7.1` and `@cybermp/browser-types@2.0.1`. In-game behavior requires verification on specific versions of Cyberpunk 2077 and CyberMP.

The main problem is that the agent receives contradictory information from two tools of the same kit. For example, `cybermp_get_event` returns two numeric IDs for `vehicleStreamIn`, while the first result of `cybermp_search_docs` promises an `MpVehicle` object. The fix priority is to remove this discrepancy in the output, then to correct the examples by topic.

## Single player as the audit baseline

CyberMP runs on top of Cyberpunk 2077. When looking for a solution we consider the full set of single-player capabilities: stock assets, TweakDB records, game systems, interfaces, animations and mechanics. If the CyberMP reference has no ready example, we check how the capability is implemented in the base game and how a CyberMP resource can use or adapt it.

For each capability we record separately what exists in the base game, how it is reachable from a resource and what happens in a networked session. Applicability can be affected by the game version, installed DLC, archive loading and `cybermp_core` settings. For example, the game includes a vanilla garage, and the `disable_garage` parameter controls its invocation in CyberMP. [Working with the REDengine API](https://docs.cyber.mp/reference/client/working-with-game-natives/) · [File delivery](https://docs.cyber.mp/guides/resources/adding-resource-files/) · [CyberMP settings](https://docs.cyber.mp/reference/server/configuration/)

## What was checked

- All **16 Markdown references**. Extracted **127 JS/TS blocks**. Each one was compiled separately in TypeScript strict with `mp` declared in turn as `MpClient`, `MpServer` and `MpBrowser`. **76** blocks passed in at least one environment. **51** reported diagnostics in all three. Some blocks intentionally assume adjacent code or application functions, so this is a queue of checks for example self-containment, not 51 defects. Material discrepancies below are tied to the applicable environment.
- **64 rows** of the server and client event tables were matched against the generated index. **22** differ in arguments or return type and **2** are missing in the corresponding index environment. An argument rename with the same type was not counted.
- **45 TweakDB records** were checked for duplicates and for traces in external lists or in the Freeroam sources. For statuses and vehicles exact strings were compared. Applicability of an object, effect or record in CyberMP does not follow from this.
- **29 CyberMP Docs summaries** are pinned to snapshot `909c0c08d7810ad136ab8b0ff2b8e0b4fdc6d569`. They are useful for navigating the guides. The offline corpus still has gaps in the Reference, Lua and archive dependency compatibility diagnostics sections.

## Changes from the audit

- The event tables and MCP search now use shared data from the declarations. RPC and starter resource examples are aligned with the installed types. Links to checkable mentions were added for part of the TweakDB catalog and disputed records are marked.
- The local camera now checks component appearance with a bounded wait. For spectator, a component search by network ID is provided. Noclip and transition into an interior are described as in-game verification scenarios. CEF and local objects show cleanup on resource stop. The server-side `mp.hashes.resref` is specified for `mp.objects.create`.
- In the player mechanics reference the spawn request, puppet readiness and movement are separated. The purpose of `perc` and the argument types for teleport, inventory and equipment are clarified. Examples of infinite constraint updates, disabling all components and freezing by teleport every frame are replaced with conditions and checks for the target mode.
- For doors, local calls and the `DoorControllerPS` type are verified. For the network scenario a stable resource key and re-application of state after streaming are specified. In workspots the link between `.ent`, `.workspot` and animation dependencies is described. Local examples use `GetPlayerObject()` and issue requests after the actor appears.
- For vehicles, the network ID and the local seat target, approximate server speed and the calibrated HUD value, local car changes and network ownership are separated. Access to `vehicleControllerPS` is clarified. Unconfirmed RPM and gear fields were removed from the speedometer. The CrystalCoat shader is described as a local visual check.
- In the native examples a presence check for `TrackMappin` was added, and slot position reading checks the component type and the result of `GetSlotTransform`. The FX reference accepts a typed effect resource. The world interaction recipe now contains a self-contained diagnostic of a single point with cleanup of the marker, prompt and timer.
- In the server reference the safezone checks positions at the moment of a PvP event and accounts for zone overlap, height and dimension. For exports, the divergence of the public guide from the pinned `MpServer` is recorded. The hash format, metadata synchronization and prerequisites of ownership transfer are clarified.
- MCP no longer substitutes the first example when there is no match or relevance is equal. For the chosen example the output states the environment, the nearest conditions of use and the declaration version where it is recorded after static checking. A link to a section opens the full source and neighboring fragments.
- Added [archive mod compatibility reference](../../skills/cybermp-dev/references/archive-mod-compatibility.md) with public sources and an example of an `.archive` and `.xl` pair from Freeroam. For the six `Workspot.*`, the output now marks search hints and points to the device and `.workspot` before `PlayInDeviceSimple`.
- A false warning about `mp.events.add` was removed. The official Lua API uses this method on the client and the server. In JavaScript and TypeScript `mp.events.on` is used for local events. Editor rules state the language of the call, and offline search points to the help on event routes. [Lua events](../../skills/cybermp-dev/references/lua-events.md)
- Added [native bridge help](../../skills/cybermp-dev/references/native-bridge.md) to offline search. It links `use_game_natives` to the client script language, separates world readiness from puppet appearance and explains hash representation.
- Exact queries for `resource.toml`, `server.toml` and `core.files` open the corresponding sections. The answer distinguishes resource launch configuration, core file delivery and client files of an individual resource. The installed MCP was verified on these scenarios and on an exact Porsche query. 189 tests passed, as did the build and the example check.
